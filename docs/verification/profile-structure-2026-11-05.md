# 職場・代表プロフィールの構成整理

## 対象と境界

Airbnbの場所と人を分ける構成を参考にし、内容を求人用へ整理する。Airbnbの非公開編集画面を再現したという意味ではない。

起点はローカルの origin/main 01e8bfd9。別ブランチの専用プレビュー変更 bb56bac8 は含めない。DB、RLS、公開同意、写真の下書き・公開経路、公開RPCの取得項目は変更しない。変更はローカルのみ。

## 編集の分類

- 職場の写真: 既存の写真管理。
- 職場の概要: unique_point、intro_crops。
- 職場の雰囲気: intro_atmosphere。
- 設備・待遇: 既存 perks 項目。
- 教え方・関わり方: 既存 style 項目。選択式の作業中の雰囲気も維持。
- 初日の案内・休憩: always_do、break_style。
- 代表について: owner_comment、intro_path、intro_joy、intro_message。

従来の intro / ask URL と保存対象は互換性のため残す。新しい入口には「問いかけ」を置かず、質問は項目内のお題として使用する。各入力値を一つの長文に結合しない。新しい自由文の保存単位は既存 texts_pending を通り、選択した欄以外を変更しない。入力ガイドと未入力集計も新しい分類に合わせる。

## 公開の分類

職場ページは写真、概要、働く環境、設備・サポート、教え方・関わり方、働く前に知っておきたいこと。未記入の節は表示しない。設備は既存の求人側スナップショットの真の値だけ表示し、未設定を「なし」と決めつけない。

代表カードからは既存の代表プロフィールへ移動する。代表のあいさつ、就農するまで、いま楽しいこと、初めての人へのメッセージを表示する。職場の回答を代表画面に再掲しない。既存の代表画面のシート形式は維持し、閉じるボタンを明示する。

仕事ごとの日程、報酬、危険箇所、持ち物は求人情報に残す。個人連絡先や非公開住所を新たに職場ページへ表示しない。代表カードに既存のマスキングを維持する。

## 検証

- 新しい自由文9項目が重複なく全て対応し、他の欄を変更しないことをモデルとDOMテストで確認。
- 旧URL、表示の分類、プロフィール保存の失敗・競合・再試行を既存と新規テストで確認。
- 職場ページと代表への別々の遷移、未入力の省略、既存フィールドの保持を公開側テストで確認。
- 実ブラウザー・実機・本番操作は未検証。この環境のChromium起動は既知のsocket制限があるため再試行しない。

本人向け既存プレビューも職場／代表へ分類し、同じ文章を重複表示しない。写真は既存の写真管理で確認し、本人の最新保存値と求人掲載時の設備・待遇が異なる場合があることを明記する。プレビューの専用ページ化は別の未公開ブランチにあり、統合時に再検証が必要。

最終確認: critical tests 1,248件成功、ESLintエラー0（既存警告19）、Vite/PWA build成功、既存の限定範囲のtypecheck成功。代表プロフィールの割り込み遷移によるnull参照を修正し、URL・履歴・求人・閲覧者変更時に閉じる試験を追加。検索指紋の差分はhashchange/popstateリスナーのadd/remove各1組だけと確認して基準を更新した。
