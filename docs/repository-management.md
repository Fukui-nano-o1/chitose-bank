# リポジトリ管理の8原則

この文書を共通ルールの正本とし、変更時はAGENTS・README・PR確認項目との整合を保つ。
別のチャットや作業環境でも、このリポジトリと本書を読むことで引き継ぐ。全チャットへ自動適用されるものではない。
既存の安全・権限・データ保護の指示を弱めない。

1. **機能ごとに所有する。** 専用UI・状態・処理は `src/features/<領域>/<機能>/` にまとめ、ページは組み立てを中心に薄くする。依存を調べ、小さな機能単位で段階的に移す。
2. **行数より役割を明確にする。** ファイルの責務と変更理由で分割する。行数だけの機械的分割、無関係な共通化、名前だけ違う重複は作らない。
3. **業務ルールの正本を一つにする。** 共有する判定・更新処理を一元化する。ただしUIの共通化を理由に、サーバー／DBの認可・検証・制約を削らない。
4. **公開リポジトリは公開可能な内容だけにする。** 秘密情報、個人情報、本番ログ、バックアップ、未解決の脆弱性の詳細は載せない。検証は合成データで行い、公開差分・PR本文・添付物も点検する。
5. **一つの目的を一つのbranch／PRで進める。** mainに入れる前に検証する。旧版・新版・コピーのファイル名で実装を併存させない。移行上必要な互換exportは転送だけにし、削除条件を明記する。
6. **適用済みmigrationは不変にする。** 過去の適用履歴を書き換えず、追加migrationで変更する。コード・DBの整合と適用順を記録する。
7. **最終commitを検証し、戻し方を残す。** 正常系だけでなく拒否・失敗・再試行など該当する異常系も確認する。lint・test・build・必要な実ブラウザ確認の結果と未実施を分け、リリース順・ロールバック手順をPRに書く。変更後は関連検証をやり直す。
8. **完了段階を区別する。** 「ローカル変更」「GitHub保存」「main反映」「本番反映」「本番動作確認」を別々に報告する。pushやbuild成功だけを本番完了と言わず、各段階のcommit・確認結果・未完了を示す。

## 最初の整理範囲：求人のいいね

`src/features/jobs/favorites/` は次の3つを所有する。

| ファイル | 役割 |
| --- | --- |
| `LikedJobs.jsx` | マイページのいいね一覧を表示する |
| `savedJobRecord.js` | 本人・求人を固定した保存結果照合と読込revisionを管理する |
| `useSavedJobMutation.js` | 画面から共通更新を呼び、連打・本人切替を扱う |

`ProfileHub`、`JobSearchMapView`、`SavedJobsView` はこの機能を参照する。
`SavedJobsView` は応募・カレンダーも扱うため、今回は移動しない。
共有UI・RPC・DB・ルート・キャッシュの仕様は変えず、依存先とテストを移動先に追従させる。

`savedJobRecord` と `useSavedJobMutation` は全呼び出し元をfeatureへの直接参照に移し、
`src/lib/` の互換入口を削除した。保存処理とrevision状態は引き続きfeature内の一つだけ。
`src/components/LikedJobs.jsx` は `ProfileHub` が使うため、転送だけの互換exportを維持する。
この最後の入口は、呼び出し元を直接参照へ移し、参照検索・いいねの回帰テスト・buildで
旧パス利用がなくなったことを確認してから削除する。

## 次の整理範囲：求人検索の一覧取得

`src/features/jobs/search/searchJobs.js` は、公開求人の取得・並び順・先読みと
閲覧数の窓口を所有する。既存の絞り込み・詳細APIと同じ search feature に置く。
`JobSearchMapView`、訪問入口、応募準備、いいね一覧からの呼び出しは維持する。
取得中の共有状態・並び順・既読記録・キャッシュキー・DB呼び出し・ルートは変更しない。

一覧取得・閲覧数・訪問入口の先読み・応募準備・いいね一覧をfeatureへの直接参照に移し、
`src/lib/searchJobs.js` の互換入口を削除した。取得中の共有状態は一つのモジュールに残す。
大きな検索画面の分割、検索条件や公開・非公開の仕様変更はこの整理の範囲外。

## 求人検索の画面の所有場所

`src/features/jobs/search/JobSearchMapView.jsx` は、検索一覧・求人詳細・応募パネルの
画面状態と組み立てを所有する。絞り込み・詳細部品・API・一覧取得と同じ search feature にまとめる。
今回は配置とimportだけを変更し、画面内部の分割・表示・操作・ルート・キャッシュ・DBの仕様は変えない。
共用UIは `src/components/`、いいね更新は `src/features/jobs/favorites/` を参照する。

既存ルートの遅延読込、求人作成プレビュー、合成データの画面検証をfeatureへの直接参照に移し、
`src/components/JobSearchMapView.jsx` の互換入口を削除した。`lazyChunk` とnamed exportの
読込契約は変更しない。検索条件・求人詳細の行き戻り・いいねの回帰テストを維持する。

削除済み4入口の再導入・旧パス利用は `scripts/feature-entries.test.mjs` で検出する。
過去の障害・作業記録中の旧パスは当時の配置を示すため変更しない。
