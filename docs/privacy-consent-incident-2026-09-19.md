## 再現と変更

旧通信処理とインストール済みSupabase SDKを使い、同意UPDATEに本文が空ストリームの204応答を与えると、1回の送信後に `TypeError: Response constructor: Invalid response status code 204`、status 0になった。共通処理の修正は先行する `d9ddf76` に含まれる（求人保存の障害記録を参照）。

今回の同意保存修正:

1. UPDATEに本人の `agreed_privacy_version` だけを返させ、保存された版数が一致した場合のみ完了する。0件・版数不一致で同意済み扱いにしない。
2. 応答が届かなかったときは、書き込みを再送せず本人の同意版数を1回照合する。照合期限は6秒。書き込み・照合のSDK自動再試行は無効。
3. サーバー障害、応答不明、認証、権限の表示を分ける。回線が原因と断定しない。
4. 連打を防ぎ、例外時も保存中表示を解除する。
5. 失敗時は既存の `app_errors` に固定の操作名・エラーコード・利用者向け文言を送信する。生のDBエラー、同意者のID、氏名、住所、認証情報を追加しない。記録の完了は画面復帰を待たせない。DB停止中は障害記録も保存できない限界がある。

RLS、同意本文、版数、本人の実データには変更を加えていない。
