# 委託者情報・電話番号の同時保存（A11の前半）

基点main: `86903e9fbdb33934577edddc9e03f633f671a335`。2026-10-18確認。

従来は電話番号の正本更新エラーを捨て、委託プロフィールのupsertが成功すれば完了表示と端末下書きの削除へ進んでいた。電話番号と委託者情報を1つのRPCで保存し、どちらかが失敗した場合は変更履歴を含め同じトランザクションで取り消す。

| 責務 | 実装 |
| --- | --- |
| 読込・本人の確認・結果照合 | `consignorRecord.js` |
| 電話の正本更新と委託者情報の条件付き保存 | `save_my_consignor_profile` |
| 利用同意の本人限定保存 | `save_my_consignor_consent` |
| 入力・比較元の端末保持 | 利用者ID付きの`cb_consignorDraft_v2` |

RPCはSECURITY INVOKER・固定search_path。画面を開いた本人のIDと`auth.uid()`が一致する場合だけ処理する。委託テーブルの管理者限定RLSと、登録情報の本人限定RLSを維持する。電話は空欄の補完のみとし、他の画面が登録した電話番号を上書きしない。電話変更は既存の`update_account_holder_self`を呼び、変更元`consignment_flow`の履歴を残す。電話番号・身元情報を委託JSONへ複製しない。

委託JSONは読み込んだ値と比較して更新する。応答だけ失った場合は両方の正本を再読込し、入力と一致した場合だけ成功とする。保存中は入力と二重送信を止める。読込失敗は空欄として扱わず、再読込の案内を出す。

端末下書きには本人IDと比較元も保存する。再読込後も、古い下書きを最新のDB行に無条件で結び直さない。変更があれば入力を残して競合を案内し、利用者が明示的に選んだ場合だけ下書きを破棄して最新内容を読む。所有者が不明な旧`cb_consignorDraft_v1`は自動復元・削除しない。他人の入力を読み込まないため、旧下書きの自動移行は未実装。

## 検証

本番から読み取った委託プロフィール列定義と登録情報更新関数を、利用者データを含まないfixtureに使用。PGliteで電話失敗・プロフィール失敗のロールバック、履歴の一回だけの追加、他の編集との競合、電話の上書き拒否、非管理者・匿名・別アカウントの拒否を検証する。

共通処理と実React画面で通常保存・片側拒否・応答紛失・結果再読込失敗・二重送信・読込再試行・競合する下書きの復元を確認する。本番利用者の登録情報を変更する試験は実施しない。
