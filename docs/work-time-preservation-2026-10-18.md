# 未入力・旧形式の勤務時間の保持（A14）

既存求人の `work_time` がnull・空欄・読取不能でも、画面の新規作成用の初期時刻8:00〜16:00が残り、別の項目を保存しただけでその時刻へ置き換わっていた。

入力変換を修正し、元のDB値を `workTimeRaw` として端末下書きにも保持する。既存の空欄・null・読取不能値は時刻欄を空にし、利用者が時刻を編集するまで元の値を送る。有効な旧表記も元の文字列を保持する。開始・終了のどちらかを利用者が変更した時だけ元の値の保持を解除し、両方揃えば新しい時刻を保存、片方が未入力ならnullを保存する。空欄を00:00として計算しない。

新規作成の初期時刻は従来どおり。読めない旧値は画面に表示し、掲載前に時刻の入力を案内する。開始・終了が揃い、終了が開始より後であることを既存の掲載確認と同じ画面計算で判定する。自動的な時刻推測、過去に上書きされた値の復元、勤務規則の変更は行わない。

検証は純粋変換の往復に加え、実LandingFlowでnull/空欄/不明の求人を開く→賃金変更→端末保存→オフライン再開→開始だけ入力→終了入力→終了を消すまで確認。既存の全44列保持、再送、掲載、コピーの試験も継続する。DB migrationは不要。
