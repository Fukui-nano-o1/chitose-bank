# 仕事の評価：受付と公開

更新：2026-09-29

- 最終作業日の終了時刻を起点に、72時間未満だけ送信できる。例：9/29 17:00終了なら10/2 17:00に受付終了・公開。
- 双方が提出しても公開を早めない。片方だけの評価も削除せず、同じ日時から公開対象になる。
- 公開する項目の範囲は従来どおり。良い点は匿名の件数、悪い点と私的メモは非公開。管理者は運営確認のため送信後から確認できる。
- 既存の仕事にも同じ受付期限を適用する。既存の評価は削除しない。

## 起点と保存の制御

`app_work_due_at` の合意日程・休日・勤務終了時刻（日本時間）を使う。終了時刻が不明なら最終日の23:59、日程自体がない既存仕事は記録済みの完了日時を使う。両方不明なら受付しない。

`applications.review_opened_at` は終了済みの起点を固定する。終了後の求人・合意日程編集、完了処理、値の上書きでは変えられない。完了操作を遅らせても72時間は延びない。

`review_window` は当事者だけが呼べる受付状態RPC。画面はサーバー時刻との差を使い、表示中の締切・復帰時の確認・送信直前の再確認で閉じる。通信確認に失敗した場合は入力を送信せず、再確認と戻るを表示する。

最後の防壁は `reviews` の INSERT / UPDATE トリガー。実際の書込時刻を `clock_timestamp()` で判定し、72時間以上なら拒否する。既存の直接INSERT、両方の農家RPC、特権ロールからの通常の書込みでも同じ判定を通す。投稿日時の偽装で回避できない。提出後の内容変更は不可、運営によるコメントの非表示は可能。

両農家RPCも完了記録・お気に入り・通知の前に受付を確認する。期限後の試行でこれらの副作用を起こさない。

## 公開と通知

公開集計の全窓口（評価バッジ、また働きたい件数、働き手・農家の信頼情報）を `app_review_published` に統一する。双方提出による早期公開条件を撤去した。時刻判定なので公開のための定期実行は不要。

受付通知は肯定・否定に関係なく同じ文面を送る。評価者名や回答内容は入れず、公開日時を知らせる。未公開内容をメールから推測できないようにする。

片方だけの評価を削除するDB関数・定期ジョブは2026-09-29の監査で見つからなかった。今回も削除処理は追加しない。
