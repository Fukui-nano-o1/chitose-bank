# 仕事の評価：両方向に40項目ずつ

更新日：2026-09-29（日本時間）

農家→働き手、働き手→農家のそれぞれで、良い点20・悪い点20の選択肢を用意する。
1ページに5分類・各4項目。良い点と悪い点は別ページにし、任意の複数選択にする。
同じ観点の良い点と悪い点は反対側で選ぶと置き換わるため、選択できる観点は各方向20個。
すべて未選択でも評価を終了できる。未選択を否定として数えない。

仕事の完了・また働きたいか（必須2問）→ 良い点20 → 悪い点20 → 確認 → 送信。
お気に入りの既存条件も維持する。確認から基本回答・良い点・悪い点を直せる。

## 保存と互換性

- 共通定義は `src/lib/reviewCatalog.js`。入力、本人の記録、管理画面、受け取った評価が同じ表示ラベルを使う。
- 農家側は従来と同じ `submit_farmer_final_review` を使い、完了記録・評価・お気に入りを1トランザクションで保存する。
- 働き手側の既存5列は肯定=true、否定=false、未選択=nullを維持。追加15観点は `traits` の `job_<key>_good` / `job_<key>_improve` に保存する。
- 農家側の既存6タグ（careful/fast/attentive/safe/work_issue/comm_issue）は変更しない。新しいタグを追加するだけで過去データは書き換えない。
- DBは方向別の許可キー、配列形式、文字列、重複、40個の上限を検証する。不正な農家側入力は完了処理より前に拒否する。
- 報酬への不満だけなら `pay_status=other`。「まだ報酬を受け取っていない」を明示した場合だけ `unpaid` として既存申告につなぐ。報酬の否定を外すとチェックも解除する。
- 確認や戻るでは保存せず、回答を維持する。働き手側は別応募・別アカウントで回答を初期化し、通信失敗時は再送できる。

## 公開とスマホ表示

肯定的な回答・タグだけを件数に集計し、評価者は表示しない。
否定のタグは評価者本人と管理者の記録にのみ表示する。
入力は最終作業の終了時刻から72時間未満に限定し、公開は72時間後。双方が提出しても早く公開せず、片方だけの評価も保持する。閲覧資格・RLSは維持する。
管理画面の「仕事の評価」では両方向のすべての選択項目が読める。

両方向の評価フローは `WorkReviewFlow` を共用する。
全画面をbody直下に配置し、見えている画面の大きさとセーフエリアに合わせる。
戻る・閉じる・下部操作は本文スクロールから分離し、ページ移動時は見出しへフォーカスする。
