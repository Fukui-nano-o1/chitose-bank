# 求人・作業委託写真の公開範囲修正（2026-10-22）

対象は情報開示検証の最優先1件。住所・緊急連絡先の開示条件はこの変更では扱わない。

## 変更

- `job-photos` と `consignment-photos` を private にする。
- 認証済みなら全オブジェクトを読める2つの SELECT ポリシーを削除。画像所有者・管理者・既存の管理者提供写真の利用者だけが自分の写真を列挙できる。
- 掲載中（既存の公開条件を満たす満員の closed を含む）の写真、または応募の当事者が閲覧できる open/closed 求人の写真に限り、認証付きダウンロードを許可する。下書き/pending、掲載を取り下げた無関係な求人、取消・拒否済みの非公開求人は拒否する。
- 他人の URL を自分の公開求人に貼っても権限を得られないよう、画像所有者と募集者の一致を必須にする。既存の管理者提供写真は非公開テーブルで利用者を引き継ぐ。管理者のサムネイル再生成も、管理者による登録に限って引き継ぐ。
- 作業委託の元データは現状管理者限定のため、写真にも新たな一般公開権限を追加しない。
- 既存URLを保存用の識別子として保ち、共通の画像表示部品がログイン中の資格で Storage を読む。画像を blob URL として表示し、最終アンマウント/ログアウト/アカウント切替で破棄する。公開URLや署名URLへのフォールバック、永続画像キャッシュは追加しない。
- 同時表示はダウンロードをまとめる。遅延読み込みと画像サイズ・配置は維持。認証付き画像は HTTP キャッシュを使わず取得する。
- ログイン情報を持たない共有リンクのプレビューは、非公開写真のURLの代わりにサイトのロゴを使用する。
- 画像の上書き・削除や求人レコードの書き換えは行わない。

## 検証

`listing-photo-db.test.mjs` は架空の画像・求人・利用者による PostgreSQL RLS 検証。
`listing-photo-access.test.mjs` と `listing-photo-ui.test.mjs` はダウンロード拒否・ログアウト・応答中のアカウント変更を含む表示検証。
既存の `test:critical` に3ファイルを追加する。全件テスト、ESLint、Vite build の結果は反映時に追記する。

## 反映順序

1. 新しい画像表示部品の本番配信を確認。
2. マイグレーション適用。適用履歴の version/name とリポジトリのファイル名を一致させる。
3. 2バケットが private、広すぎる2ポリシーが消えていることを本番DBで確認。
4. 検証報告書の2画像URLに認証なしの HEAD を実施し、画像を返さないことを確認。生URLや利用者のIDはコミットしない。
5. 本番の読み取り専用ロールシミュレーションで、第三者の一覧取得拒否と所有者の正当な読み取りを確認。

## 制限と復旧

すでに第三者の端末に保存された画像を回収できる変更ではない。過去の悪意ある取得の有無はこの修正の検証から判断できない。
本番の他人のアカウントでログインせず、実利用者の求人をテスト用に書き換えない。
表示に障害が出た場合は写真を代替表示として修正する。公開バケットや全会員の一覧権限へ戻さない。
