# 会話の詳細から直接進む

更新：2026-09-29（日本時間）

情報を表示する行と、同じ情報へ進むためのリンクが重なっていた。
求人プレビューを開いてから詳細へ進む中間画面と、どの仕事か分からないカレンダーへのリンクを整理した。

| タップする項目 | 行き先 |
| --- | --- |
| 求人名のカード | この求人の詳細ページ。戻る先は元の会話 |
| 相手の名前 | 相手の公開プロフィール。農家／働き手を区別 |
| 日程・時間 | この応募IDの予定詳細。役割も合わせ、「戻る」は元の会話へ |
| 集合場所 | 許可された集合住所の地図を別タブで開く |
| メッセージを通報 | 会話の中から対象を選び、理由を入力する既存の通報画面 |
| この画面を報告 | チャットについての画面報告フォーム |
| 使い方・お問い合わせ | チャットのヘルプ |

仕事の状態は求人カードにまとめる。見送り・失効・取り消しでは日程と集合場所を表示せず、
予定が残っているように案内しない。完了した仕事は既存の予定詳細で記録を確認できる。
通報するメッセージがない会話ではメッセージ通報の項目を表示しない。
画面報告とヘルプは利用できる。

各遷移時に会話の詳細を閉じ、開いた先が手前の画面に隠れないようにする。
入力中のメッセージは既存のメモリ上の下書きに保持する。
該当応募が見つからない場合に、同じ相手の別応募を選び直す処理も削除した。
取得権限・公開範囲・メッセージ送信／通報の保存処理は変更しない。

検証：`scripts/chat-ui.test.mjs` で直接遷移、農家・働き手の相手と応募の対応、見送り等の条件、
地図リンク、ヘルプ・画面報告・メッセージ通報、下書き維持、画面縮小と閉じる操作を確認。
`scripts/schedule-ui.test.mjs` で会話へ戻る操作と、他の応募の戻り先を引き継がないことを確認する。
評価画面の改修を含め、`npm run build` は202テスト成功・ESLintエラー0で完了。
ブラウザから検証サーバーへの接続は環境により遮断されたため、目視とiPhone実機の確認は未実施。
実利用者へのメッセージ送信・試験通報は行っていない。

https://www.airbnb.jp/help/article/145 と「プロフィールに表示される情報」
