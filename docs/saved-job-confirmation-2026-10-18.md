# いいね・解除・取り消しの確定表示（A10）

SavedJobsView は解除DELETEの結果を確認せずカードを消し、「元に戻す」も保存前に消していた。LikedJobs と JobSearchMapView にも別実装があり、応答紛失・例外・23505で実際の保存状態と♥が食い違った。

3画面の変更処理を `savedJobRecord.js` と `useSavedJobMutation.js` に揃えた。本人IDと求人番号を固定し、現在のセッションを保存前後に確認する。既存の本人RLSと主キー(worker_id,job_number)を使用し、DB構造や権限は変えない。

INSERT／DELETEの応答に関わらず本人・求人を絞った正本を読む。解除は行がないこと、追加は行があることを確認した後に♥・一覧・共用キャッシュを変える。23505単独では成功にしない。読込／照合失敗は旧表示を保ち、結果を確認できない旨と再試行を案内する。再送でのINSERTは主キーが重複を防ぎ、DELETEは既にない行でも現在の不在を確認できる。

求人ごとの同期ロックで連打を止める。「元に戻す」は再保存が確認できるまで残し、処理中に10秒タイマーが消さないよう停止する。失敗後にも押し直せる。本人が切り替わった応答で別の画面を更新しない。保存後に古い一覧の応答が到着して♥を巻き戻さないよう、読込開始時と確定時の版を比較する。検索のいいね一覧も読込失敗を空配列と扱わない。

検証は実Supabase SDKと隔離通信で行う。通常追加／解除、応答紛失、既存行への追加、0件DELETE、拒否、照合失敗、本人切替を確認。実Reactのステータス・プロフィール・検索で失敗時の保持、応答紛失、連打、取り消し失敗／再試行、古い一覧の遅延到着を確認した。本番ユーザーのいいねは変更していない。

異なる端末が独立して行う追加／解除は、各処理後に取得できた状態を表示する。端末間のリアルタイム同期・永続的な操作履歴・通信回復後の自動再送は追加していない。意図的な再操作は引き続き可能。
