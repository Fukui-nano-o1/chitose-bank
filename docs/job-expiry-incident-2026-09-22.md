# 終了した求人が掲載一覧に残る問題（2026-09-22 JST）

調査開始時の main: `7d9151ab08390a4e2265791d367fae1609e94edb`。

## 確認した原因

1. `src/lib/searchJobs.js` の `orderSearchJobs` は、8月5日の旧方針に従い、終了求人を削除せず一覧末尾へ追加していた。終了帯の表示を修正しても検索からは消えない。
2. `mapJobPublicRow` が取得時に算出した `expired` を検索キャッシュへ保存し、復元時に再判定していなかった。日付の経過や通信停止中には古い判定が残る。
3. `FarmerDashboard` も取得時に分類した「公開中」「期限切れ」を保存していた。検索・農家画面とも、終了時刻による再描画がなかった。
4. 日程の終了判定が重複し、端末のタイムゾーンに依存していた。終了時刻ちょうどではなく、その分を過ぎてから終了していた。

本番DBの読み取りでは `open` 3件中1件が日本時間の過去日付だった（個人情報は取得していない）。表示の正しさをDBの状態変更や次回通信だけに依存させない。

## 修正後

- `jobEndTimeMs` / `isJobEnded` を共通判定とし、日本時間の最終日・勤務終了時刻で終了する。時刻が不明な場合は翌日0時。日程が不明な場合は終了と推測しない。
- 検索・関連求人・検索候補・先読みの並びから期限切れと `closed` を除外する。期間内の満員求人は従来どおり末尾に表示する。
- キャッシュ復元時、終了時刻の到来時、画面復帰時に再判定する。終了判定のための追加通信はしない。
- 農家の一覧は現在時刻で分類し直す。公開歴のない下書きは、期限が過ぎても再開できる。
- 過去の求人、応募、契約の記録は削除しない。履歴や共有リンクから詳細を確認でき、期限切れの詳細では新規応募を停止する。確認ボックスを開いたまま期限を迎えた経路も停止する。
- DBのテーブル・権限・cron・保存済み求人には変更を加えていない。

## 検証

`npm run build` は `test:critical` → ESLint → Vite/PWAビルドを実行する。

追加した終了判定12件、農家分類5件、実際のReact画面を使うUIテスト1件を含め、合計79件が成功。
UIテストはサーバー応答を停止し、初回描画、古いキャッシュ、日付跨ぎ、終了時刻ちょうど、復帰、詳細、関連求人、応募確認中の終了、取得結果の再整列を検証する。

再現環境では追加依存パッケージの既存インストール先を `CB_TEST_NODE_MODULES` で指定した。通常のクリーンインストールでは package-lock.json の jsdom / pglite を使用する。
