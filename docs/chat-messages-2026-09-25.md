# メッセージ画面の改修と確認手順

2026-09-25（日本時間）。Airbnb公式の Messages tab の考え方を参考に、仕事単位の受信一覧・検索・状態の絞り込み・会話の詳細・定型文を実装した。既存の応募・採用・日程承認・通報・履歴保全の窓口は維持している。
参考: https://www.airbnb.com/resources/hosting-homes/a/getting-the-most-out-of-the-messages-tab-678 （2026-09-24確認）

## 操作

1. 下部「チャット」からメッセージ一覧を開く。相手の名前、仕事名、求人番号で検索できる。「未読」「進行中」「終了」「運営」で切り替える。
2. 仕事ごとに会話を開く。上部に相手・求人番号・日程を表示。「詳細」から集合場所、仕事の内容、カレンダー、メッセージ通報へ進める。
3. 「定型文」は入力欄に文章を追加する。入力済みの文は残す。Enterは改行、送信はボタンのみ。農家の日程案・働き手の日程承認も残している。
4. 通信失敗時は入力を残し「同じ内容で再送」。送信ごとのUUIDを変えず、DBの主キーで二重登録を防ぐ。送信結果が分かるまで内容を固定する。既に届いていれば再取得で完了扱いにする。
5. 「この画面を報告」はPC・スマホのメニュー、一覧、会話の入力欄・詳細、運営チャットにある。元の作業を残したまま相談を開く。

未送信の文章は本人と会話ごとにメモリに保持し、画面遷移から戻ると復元する。再読み込み・アプリ終了・ログアウトで消える。平文のチャット本文をlocalStorageへ追加保存しない。一覧のメッセージ要約もメモリのみで扱う。計測への追加送信は行わない。

## スマホの修正

チャット本体をvisualViewportの位置・幅・高さに固定し、会話部分だけをスクロールする。詳細・仕事の内容・日程案・日程確認・通報は、常に上部に閉じるボタンを置く共通シートにした。通常チャットと運営チャットは同じ高さ処理を使う。

全headerに対するモバイルの `padding: 0 16px !important` が、各画面のsafe-areaも消していた。適用対象を `.app-header` のみに限定した。既存の報告画面・表示サンプル・ヘルプにも効く修正である。また拡大していなくても、キーボードで狭くなった表示領域に既存の全画面パネルが追従するようにした。

## 検証

- `scripts/chat-ui.test.mjs`: 実React画面をJSDOMで動かし、検索・絞り込み・要約、失敗と再取得、定型文、画面移動後の下書き、応答消失と同一UUID再送、二度押し、送信期限、別会話への遅延応答、非表示時の既読抑止、終了した会話、報告の入口、運営チャットを確認。
- 320px幅・キーボード相当の290px高・表示位置の移動・横向きに相当するサイズ変更で、画面とシートが表示領域に追従することを確認。実際の共通CSSを含め、ヘッダーのsafe-areaが強制上書きされないことを検査。
- `scripts/admin-reports.test.mjs`: 表示サンプルと手順書の往復、拡大・位置移動・キーボードのみの高さ変更、閉じる操作を確認。
- `scripts/chat-db.test.mjs`: Postgres（PGlite）で1,200件以上の履歴から仕事ごとの最新1件を返すこと、240文字への制限、別人の会話を返さないRLS、未ログインの実行拒否を確認。
- `my_chat_inbox_previews` は SECURITY INVOKER。既存の当事者RLSを通る読み取りのみ。DBへ適用し、権限と索引を確認する。Supabase CLIが環境にないため、UTC時刻でmigrationファイルを作成し接続ツールから適用した。

ログイン済みの実機iPhone、実在する利用者どうしの本番送受信は未検証。試験には架空データだけを使用し、本番の利用者へメッセージを送っていない。
