# 写真の再送・枚数上限・共有参照の保護（A05/A06、A11の写真自動処理）

共通アップロードは、保存する画像のSHA-256と本人フォルダから不変の保存先を決める。同じバイト列を同じ用途で選び直しても同じパスを使用する。上書きはしない。応答紛失・重複エラーでは同じパスをダウンロードして全バイトを照合し、一致する場合だけURLを返す。確認できなければ手動再試行を案内する。本文画像とサムネイルは独立して照合し、未確認のサムネイルURLを返さない。

本人をアップロード前後に確認する。求人フローでは画面の所有者も渡し、別の本人へ切り替わった画像を現在の入力へ追加しない。MIMEと拡張子を合わせ、新しい保存先は `本人/v2/用途SHA256.拡張子` とする。既存URLは移動しない。管理者向け一括圧縮でも、この新しい不変領域を上書き対象から外す。

危険箇所と通常写真は同期ロックで二重選択を抑止。配列へ反映する時点の最新値で重複と2枚/10枚上限を確認する。危険箇所の保存中も親フローの保存・次へを待機させる。画面を閉じたり別求人へ移った後の遅い応答は入力へ反映しない。

委託画面を開くだけで動いていた `healConsignPhotos` を撤去した。この処理は古いJSON全体を書き戻した後、0件更新や共有参照を確認せず旧写真を削除していた。圃場写真は案件へ呼び出され、案件・契約へURLが複製されるため、旧写真を削除しない。既存写真はそのまま表示できる。画像の参照付け替えや過去の欠落データの補修は行わない。

## 検証と境界

実Supabase SDK＋隔離Storage通信で、通常・並行送信・応答紛失・照合失敗後の再送・同サイズ別内容・本人変更・任意サムネイル失敗を試験。実Reactの写真入力で同時操作・枚数・入力保持・再試行・求人切替・アンマウントを確認する。本番のStorage RLSを読み取り、job-photosの本人先頭フォルダ制約と、委託/経営写真の管理者限定書込みを維持。DB migrationは不要。実利用者の写真の追加・削除は試験で実行しない。

同じ原本でもブラウザの圧縮結果が異なる場合は別バイトとして保存される。参照未登録の画像が一切残らない保証や、過去の重複画像の自動掃除は含まない。DB参照保存前に終了した画像は保持し、参照全体を確認せず削除しない。旧管理者ツールのサムネイル後埋めとJSON書戻しは別の残課題。委託の進捗・前払・貸与登録簿・圃場編集の保存経路もこの変更とは別。
