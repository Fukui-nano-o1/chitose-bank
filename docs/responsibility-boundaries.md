# App・求人作成・共通utilsの段階的な責務分離

基準: `458e68bc`。今回の目的は配置を変えるだけでなく、変更理由の異なる処理に所有場所を設けること。
一括で書き直さず、求人モデル、アプリナビ、掲載確認表示を別コミットで確認する。

## 今回の境界

| 親 | 切り出した所有者 | 親に残す責務 |
| --- | --- | --- |
| `src/lib/utils.js` | `features/jobs/model/jobStatus.js` が求人の終了・下書き・一時非公開判定を所有 | 他領域の既存ヘルパーと互換export |
| `src/lib/utils.js` | `features/jobs/model/jobPresentation.js` が取得済み求人行の表示変換・報酬/日程ラベルを所有 | 求人の取得・公開範囲の決定は行わない |
| `src/App.jsx` | `app/navigation/MobileNavigation.jsx` がモバイルタブ、選択表示、バッジ、操作を所有 | 認証・取得・URL同期・入力画面中の表示可否 |
| `features/jobs/create/LandingFlow.jsx` | `components/ListingReview.jsx` が確認本文の飾り、未設定表示、編集タブ、報酬表示を所有 | 入力state、プレビュー材料、保存・掲載、URL、補助編集モーダル |

依存は次の向きにする。新しい求人モデルは旧utils、UI、DOM、Storage、APIを参照しない。

```text
App → MobileNavigation → 共用UI / 既存の予定route読取
LandingFlow → ListingReview → JobDetailBody / 既存表示ルール
求人取得・一覧判定・期限時計 → jobs/model
旧utils → jobs/model（互換exportのみ）
jobPresentation → jobStatus
```

公開求人変換の公開範囲は従来どおりDBの応答が決める。フロントで新しい項目を取得したり、
マスクされた値を補ったりしない。最低賃金、掲載同意、認証・認可、保存API・DB列、
競合保護、ルート形式、キャッシュのキーと寿命は今回変更しない。

## 互換入口

`utils` の7つの求人exportは新モジュールの同一関数を転送する。コピーや二重の状態は持たない。
まず求人一覧取得・一覧分類・期限時計を直接参照へ移した。他の利用元は一括変更しない。
残る利用元を段階移行し、参照検索、互換性試験、既存回帰試験、buildで利用ゼロを確認してから転送を削除する。

## 検証と戻し方

- 新しい所有境界の試験は `test:critical` に登録する。
- 求人モデルは全表示列、マスク、旧行、元データ非変更、関数の同一性と既存の期限試験で確認する。
- ナビは訪問者/働き手/農家、役割と能力、項目編集からの帰路、再タップ、入力保護を確認する。
- 掲載確認は未設定、条件別編集入口、取得失敗/再試行、callbackの同一入力、既存の確認→編集→確認を検証する。
- Chromiumは合成データのみ。外部リクエストを遮断し、既存の掲載browser試験にナビの履歴・再読込試験を加える。
- 実行結果と実行できなかった段階はPRに記録する。ブラウザーの画面サイズ試験を物理iPhone/Safari/Android検証とは呼ばない。
- DB変更は無い。問題があれば該当する抽出コミットをrevertし、全体buildと対象browser試験を再実行する。
- このPRはdraftまで。mainへのマージ・本番反映は別途判断する。

## 残る混在

これは全面分割の完了ではない。Appには認証・通知・ルート同期・メニュー/オーバーレイ、
LandingFlowには入力state・下書き保存/再開・掲載調停・補助編集、utilsには日程・応募段階・
プロフィール・UI定数などが残る。次の候補はAppのルート同期境界だが、履歴・認証復帰の
依存を先に調べ、今回と別の小さい変更として扱う。
