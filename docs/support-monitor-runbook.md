# 千歳 モニター・運営改善の手順

更新日：2026年9月24日

目的は、初めて使う人が迷った場所を見つけ、目的の操作を最後までできるようにすることです。報告の件数よりも、操作が止まった原因と、修正後に続けられたかを確認します。

## モニターの方へ

1. 普段使っているスマートフォンでサイトを開いてください。最初は操作の説明を受けずに、次のうち運営から指定された目的を試してください。
2. 迷ったり止まったりしたら、「ヘルプ・お問い合わせ」を開きます。ログインできない場合も、ログイン画面の相談の入口を使えます。
3. 困っている操作と「操作が止まっている」「使いにくい・迷った」「改善を提案したい」を選びます。表示された案内で解決しない場合は、そのまま相談を送れます。
4. 「何をしようとしたか」「何が起きたか」「どうなると思ったか」を、分かる範囲で書いてください。説明できなくても、困った場所だけで構いません。試験での報告は、本文の先頭に「【モニター】」を付けてください。
5. 診断情報は送信前に確認できます。添付するかどうかは選べます。パスワード・認証コード・他人との会話の全文は書かないでください。
6. 送信後は元の操作に戻れます。「相談履歴」で運営の回答を確認してください。案内を試しても直っていなければ、同じ相談に追記してください。

送信に失敗した場合は、送信完了とは扱われません。入力が残っていることを確認し、接続が戻ってから再試行してください。下書きは最後の編集から7日間、このブラウザで再開に利用できます。期限を過ぎた下書きは次回読み出す際に削除します。端末の保存領域が使えない場合は画面の案内に従ってください。

ログインせずに送った相談は、送信したブラウザで回答を確認します。ブラウザの保存領域を削除したり「この端末の受付情報を消す」を実行したりすると、その相談を開けなくなります。共用端末では、利用後に下書きとこの端末の相談履歴を削除してください。

### 初回の確認テーマ

約15名が同じ操作だけに集中しないよう、最初の確認テーマを5名ずつ分ける案です。担当外の問題も報告できます。

| 人数の目安 | 目的 | 確認すること |
| --- | --- | --- |
| 5名 | 新規登録・ログイン | 登録済みの方の入口、メール待ちの案内、困った時の相談、ログアウト後の状態 |
| 5名 | 仕事を探して内容を理解する | 日程と募集状況、仕事内容、報酬、必要な条件、元の一覧への戻り方 |
| 5名 | 自分の予定と必要な情報を確認する | マイページ・カレンダー・チャット・通知書への行き方、戻る操作、次にすること |

実際の応募・掲載・採用・契約確認は相手へ影響するため、運営が確認用として用意した対象で行います。確認できる対象がない操作は、未確認として残します。実際に働く意思のない求人へ確認目的で応募しないでください。

## 運営の進め方

### 開始前

- 最新版で「ログイン前から相談できる」「送信完了後に履歴を開ける」「運営の回答が本人に見える」「元の画面へ戻れる」を確認します。
- 新規登録メールは、本番の受信まで別途確認します。送信APIの成功や相談機能の完成だけで「届く」と判断しません。
- 説明をする担当と、報告の確認・回答をする担当を決めます。同じ人が兼任する場合も、報告を確認する時間を確保します。
- モニターには「分からなかったことをそのまま報告してよい」と伝えます。先に正解の操作を教えると、初見で迷う場所を確認できません。

### 報告が来たら

1. 管理画面の「通報・サポート」を開きます。「要対応」から、先に進めない報告を先に確認します。これは本人が選んだ影響の申告であり、障害の重さが確定したわけではありません。
2. 受付番号・操作・本文・診断情報を確認し、確認を始めた案件の状態を更新します。診断情報がない場合も、受付を取り消さないでください。
3. 再現できた事実と、まだ確認できないことを分けます。同じ症状の報告を検索し、別の原因まで一括して解決扱いにしないでください。
4. 利用者に見える回答には、確認したことと、次に試せる操作を書きます。「調査中」だけで終わらせず、操作を続ける方法が分かる場合は具体的に案内します。確認できない場合は、その旨を伝えます。
5. 修正したら、問題が出た端末や操作に近い条件で、元の目的が達成できるか確認します。回答を送っただけでは完了にしません。
6. 対応を完了する際は、修正した点と再確認の方法を本人に伝えます。本人から未解決の追記があれば、同じ相談で確認を続けます。

運営内部のメモと、本人に見える回答を混同しないでください。他の人の氏名・相談本文・認証情報を回答に貼り付けないでください。人や求人への通報、未払い、事故などは、それぞれの既存の対応手順で扱います。

### その日の振り返り

次の数字と、代表的な相談の受付番号を記録します。以下は計測する項目であり、実績値ではありません。

| 項目 | 数え方 |
| --- | --- |
| 操作が止まった人数 | 同じ人の連投を重複させず、確認できた人数を数える。ログイン前の相談では本人の識別ができない場合があるため、無理に人数と断定しない |
| 自力で完了できた人数 | 対象の操作を試した人数を分母にし、案内なしで完了した人数を分子にする |
| 案内後に完了できた件数 | 本人の追記や一緒に行った確認で、完了を確認した相談を数える |
| 対応後も直らなかった件数 | 対応済みにした後、同じ問題が続いていると分かった相談を数える |
| 次に直す問題 | 操作が止まる問題を優先し、担当と、修正を確認する方法を1件ずつ決める |

相談の多さだけで優先順位を決めません。報告の入口にも到達できなかった人、メールが届かず参加できなかった人は、相談一覧に出てこないため、開始・終了時に口頭でも確認します。

## 公開作業の確認事項

- フロントエンドのプライバシーポリシーは `v4.7-2026-09`。同意の保存はデータベースの現行版数と一致している必要があります。
- 対応するフロントエンドの公開成功を確認してから、`supabase/operations/activate_support_privacy.sql` で現行版数を切り替えます。別の版が設定されている場合は、原因を確認してから対応します。
- 任意の利用状況の計測は別の選択です。プライバシーポリシーへの同意やサポートの利用だけで、計測を許可した扱いにしません。
- メールの到達、実際の応募・契約、実端末でのPDF保存については、確認していない項目を確認済みと報告しません。
