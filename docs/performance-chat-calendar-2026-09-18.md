# チャットとカレンダーの表示待ちを減らす（2026-09-18）

チャット一覧の付加情報を待つ処理と、カレンダー操作時の全予定走査を減らした。変更前は main の `8ddc5cd25061e54b82223f7289d719495f286e5c`。今回の比較は実際の React コンポーネントを JSDOM で動かし、通信の到着順と失敗を制御した結果である。本番端末での表示秒数、LCP、日程保存から画面反映までの時間は確認できません。

採用したのは、React 公式が説明する、不要な通信の直列化を避けること、同時リクエストをまとめること、古い応答を無視すること。既存の取得窓口とキャッシュに組み込んだ。資料確認日：2026-09-18。[React: Fetching data with Effects](https://react.dev/reference/react/useEffect#fetching-data-with-effects)

カレンダーでは予定が変わったときだけ日付別の索引を作り、日付選択やドラッグで再利用する。`useMemo` は更新時の不要な再計算を省くために使うもので、実機での初回表示改善を保証するものではない。資料確認日：2026-09-18。[React: useMemo](https://react.dev/reference/react/useMemo)

| 対象 | 変更前 | 変更後 |
| --- | --- | --- |
| キャッシュ表示中のチャット | 相手・求人情報がそろうまで新しい行や状態も待つ | 応募情報の到着で行と状態を更新し、既存の相手名・求人名は保つ |
| 相手名・求人名 | 雇い手、働き手、求人の取得をまとめて待つ | 各取得結果を届いた順に反映 |
| 返信順 | 応募取得→付加情報の完了→メッセージ時刻取得 | 応募取得→付加情報とメッセージ時刻を並行取得 |
| 相手の頭文字 | 未読数の取得後に開始 | 未読数と独立して開始 |
| 未読の重複取得 | 新着や復帰のたびに同時取得 | 取得中の要求をまとめ、最後にもう一度取得して新着を拾う |
| チャット一覧の再取得 | マウント時のみ | 既存の応募更新・復帰の合図も受け取る |
| カレンダーの日付検索 | 各表示日で全予定の集合を検索 | 日付から該当する予定の添字を取得 |

チャット一覧の再取得は既存の `useRefreshTick` に合わせて最短間隔5秒でまとめ、非表示中は保留する。既存行の Realtime 状態更新は受信時に反映する。新規行や切断中の変更がすべて無待機で反映されるという意味ではない。

古い履歴で新着の時刻を戻さず、取得中の応募更新を古い応募応答より優先する。付加情報は該当する項目だけを重ねるため、取得中に変わった応募状態を戻さない。応募の片側の取得が失敗した場合も一覧を空にせず、エラーが返った付加情報は既存表示を保つ。再取得や画面離脱で不要になった応答は反映しない。

カレンダーの日付決定は既存の `entryWorkDays` を使い続ける。合意日、希望日、休日、各予定の順番、色、名前、日付選択の対象を変更しない。応募の2つの役割別クエリ、取得対象の状態、自己応募の重複除去、求人の当事者向け取得窓口、書き込み操作とDB権限も変更しない。

検証は変更前後で各18ケースを実行し、どちらも想定した挙動との一致を確認した。「変更前の成功」は元の待ちや巻き戻りの再現を含み、改善済みという意味ではない。変更対象2コンポーネントと取得・キャッシュ・日付処理は実コード、Supabase の通信と周辺の表示部品は代替した。実アカウントへのログイン、本番データの更新、メッセージ送信はしていない。

| 検証条件 | 変更前 | 変更後 |
| --- | --- | --- |
| 未読取得が未完了 | 相手の頭文字取得は未開始 | 頭文字を先に表示できる |
| キャッシュ1行、応募取得で2行、付加情報は未完了 | 旧状態の1行 | 更新した状態の2行、既存の名前は維持 |
| 雇い手名・働き手名・求人の到着順を変更 | 全部を待つ | 到着した情報をそれぞれ表示 |
| 返信時刻取得の開始 | 付加情報完了後 | 付加情報が未完了でも開始 |
| 応募取得中または付加情報取得中に状態更新 | 古い取得結果で状態が戻る | 新しい状態を維持 |
| 履歴が新着より遅く到着／Realtime配信が前後 | 並びが戻る | 新しいメッセージ時刻を維持 |
| 応募取得のエラー／付加情報のエラー | 一覧や付加情報を失う | 既存表示を維持 |
| 正常な空の一覧／自分への応募 | 空へ更新／1スレッド | 同じ |
| 更新合図の後で古い相手情報が到着 | 一覧は再取得されない | 新しい一覧を表示し、古い応答は無視 |
| 初回未読取得中に新着3件、完了後の後追い取得を含む | 4通信 | 2通信（初回1回＋後追い1回） |
| 画面離脱後の相手情報 | 保存済み一覧を変更しない | 同じ |
| 合意日・希望日・休日・いいねの混在 | 日付・文言・色・選択対象を記録 | 記録と一致 |
| 予定500件、表示181日、日付選択1回 | 全予定に対する日付判定181,500回 | その判定は0回。日付別索引で参照 |

最後の行は `Set.has` による全予定走査の回数であり、全計算が0になるわけではない。初回には索引を構築し、更新時にも日付の参照・その日の予定の描画は必要になる。通信待ちや実機速度をこの回数から秒数に換算していない。
