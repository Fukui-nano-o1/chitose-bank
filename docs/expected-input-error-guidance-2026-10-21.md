# 想定される入力エラーと復帰案内の検証

確認日：2026-10-21。対象はGitHubの主要入力保存経路。今回の目的はエラー自体の撤去ではなく、状態を正しく伝え、利用者が次に行う操作を明確にすること。

## 方針

「保存結果不明」を「保存失敗」と断定しない。「この画面に入力が残る」と「端末に下書きを保存済み」を区別する。認証・同意・権限・競合を、すべて通信の再試行へ誘導しない。

`src/lib/inputRecovery.js` に案内を集約し、プロフィール・登録・コピー・当日報告・仕事の内容確認・写真・いいね・委託の保存窓口から利用する。求人の掲載/同期案内と下書き一覧も同じ方針に合わせる。`#/help/recovery` に7項目の説明と相談ボタンを追加する。

成功判定、比較保存、再送ID、保存する内容、入力保管、DB権限、通知処理は変更しない。例外分類のみ、委託の「保存後に端末側の記録整理が失敗」を `CONSIGNMENT_ACK` とし、保存結果不明から分離する。既存のエラー記録を削除・自動解決しない。

## 確認した状態と案内

| 状態 | 検証した挙動 | 利用者への案内 |
|---|---|---|
| 読込失敗 | 登録済みの情報を読めない間、新しい登録を開始しない | 入力を残して通信を確認し、元の読み込み/登録ボタンから再確認 |
| 応答紛失 | DB側では保存済みでも、完了表示にせず結果未確認を維持 | 保存済みの場合もあると説明。同じ対象の案内された確認操作を行う |
| 再送時の追加入力 | 当日報告の再送で前回の内容を確認し、追加編集は未送信として区別 | まず前回の内容を確認することを明記 |
| 同じ項目の競合 | 他の編集者の値と、呼出元の入力を保持 | 入力を控えて最新内容と照合。保存を繰り返して上書きしない |
| ログイン状態/アカウント変更 | 別アカウントの画面から旧所有者の登録を開始しない | 閉じる前に入力を控え、アカウントを確認。ログイン画面が出た場合は同じアカウントを使う |
| 端末保存の失敗 | 操作を保持できない場合、当日報告のRPCを呼ばない | 空き容量・保存設定を確認。サイトデータ削除や別端末への移動を安易に勧めない |
| 保存済み・端末確認の失敗 | コピー/委託の保存後、端末の記録整理に失敗しても、再試行で同じ保存結果を確認 | 保存済みと明示。新しいデータを作り直さない |
| 同意未完了・権限不足・応募あり | 既存の拒否条件を維持し、理由別の案内を選ぶ | 同意の確認、アカウント/対象の確認、応募状況の確認へ案内。時間経過だけで直るとは言わない |
| 不明な拒否・内部エラー | 未登録コードは既知の復帰状態に分類しない | 原因不明のまま維持。繰り返す場合の問い合わせ先を示す |

`Failed to fetch` だけから「リクエストが届かなかった」「端末原因が大半」と断定していた管理者向け説明も変更。通信・DB時間切れ・権限拒否の原因は記録だけでは確認できないこと、結果照合/調査が必要なことを明記する。

## 試験の根拠

- `scripts/input-recovery.test.mjs`：実際の保存関数へ通信断・読込失敗・競合・アカウント変更・保存領域拒否・確認記録の整理失敗を注入。案内と、書込回数/内容保持/同一操作の再利用を同時に確認。
- `scripts/device-drafts-ui.test.mjs`：実ReactとSupabase SDKのHTTPアダプターで、掲載応答紛失・競合の案内、端末下書きの保持、同じ掲載操作の確認を検証。
- `scripts/profile-record-ui.test.mjs`、`scripts/consignor-ui.test.mjs`：競合案内が実画面に出て、入力と他の編集内容を保持することを検証。
- `scripts/copy-retry-ui.test.mjs`：同じコピーの再確認案内と、元の操作から編集画面へ復帰することを検証。
- `scripts/help-image-ui.test.mjs`：実HelpCenterに新しい7項目が表示され、相談ボタンが開き、保存を発生させないことを検証。
- `npm run build`：上記を含む全671件が成功（失敗・取消・スキップ0件）。lintはエラー0件・既存警告19件。本番用ビルドとPWA生成も成功。CI/本番反映結果はPRに記録。

最初の全回帰では、旧文言を期待していた委託者画面と求人下書き画面の表示検査が失敗した。新案内の具体的な内容を検査するよう更新し、入力保持・保存状態・書込回数の検査は維持して再実行した。

## 検証の境界と残課題

想定される復帰状態であっても、原因が正常・無害だと証明したものではない。実機2台、実ブラウザの容量制限/強制終了、実際のメール/通知到達は今回検証していない。本番の利用者データや通知を試験で作成/変更しない。

全画面の全入力・全通信例外を網羅したとはしない。質問/回答・地域投稿など、今回共通窓口に接続していない追記系の案内と再送条件は別途確認する。旧移行履歴の対応86件、管理者公開時の失敗後閉鎖/対象版照合、満額保証の仕様判断は今回変更しない。
